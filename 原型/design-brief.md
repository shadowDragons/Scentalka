# Scentalka 原型设计简报

依据：根目录《产品文档.md》，包含第 18 节默认预设。此文件记录原型范围及待确认的视觉方向，不改写产品需求。

## 设计目标

设计一个可在桌面浏览器体验的英语生活模拟原型。首屏必须同时看懂主角在哪里、现在与谁交流、当前有什么待办，以及下一条输入会发送到哪里。游戏中所有可见文字为英语。

原型使用文档中的预设人物和剧情数据，不依赖模型密钥或现有数据库。模拟回复应与实际状态相符，不能把界面演示描述为已接入真实 AI。语音录制与播放能力按浏览器实际支持实现；不可用时有清楚的英语状态和文字回退，不伪造录制成功。

## 布局与观看条件

- 主界面承担生活现场与持续沟通的功能，常用操作保持在同一屏内。
- 桌面优先，以 1440 × 900 为主要检查尺寸，同时检查较小笔记本视口；不加手机或浏览器装饰外框。
- 中央约 58%～65% 宽度用于单层 2D 场景，右侧约 30% 用于 IM；任务和物品采用可收起面板，避免一开始同时展开所有信息。
- 顶栏保留日期、游戏时间、地点、到访身份、暂停或行动状态；底部输入固定显示当前入口及接收对象。
- 阅读与输入期间游戏时钟不自动走动；待结算成本、行动预计耗时和关键节点确认清楚可见。
- 键盘焦点和快捷键可见。地图不依赖鼠标点击控制主角，指令驱动行动；普通按钮仍可聚焦操作。

## 原型覆盖

1. 默认世界进入与继续：直接使用 Chris、Sarah、Mia 等预设，不增加英语等级或教学流程。
2. Home、Hospital、Road 三个单层场景；按指令移动与切换，位置和时间与任务保持一致。
3. NPC 联系人及公开服务目录；公共、私人及现场联系范围有明确状态。
4. 独立 NPC IM：文字和语音消息、未读、播放、转写、发送状态；不自动播放新语音。
5. 三种输入上下文：NPC IM、World、Assistant；切换不把草稿误发给另一个对象。
6. 任务、日程、物品和只读事件历史；交付物品后归属真正改变。
7. 行动预览、关键节点结算、事件打断、继续与停止计划；停止不撤销既有预约。
8. 英语助手：解释已展示信息，提供表达建议，未经用户发送不创建主角台词。
9. 预设编辑：人物、身份与代表性节奏参数；先预览差异再保存；固定地图不编辑。
10. 每日复盘与继续同一世界；原型本地状态保存，演示存档与当前世界区分。

## 验证流程

- 家庭流程：与 Sarah 商量钥匙 → 走到玄关 → 拿钥匙 → 实际交付 → 查看更新后的物品与事件。
- 医院流程：公共目录找到 Emma → 提出并确认预约 → 拿证件并前往 → 登记 → 等待叫号 → 查看消息并进入诊室。
- 道路流程：出行发生有来源的延误 → 查看或播放通知 → 有界等待 → 主动停止 → 取消剩余路线 → 改为步行，预约仍保留。
- 预设流程：修改允许的参数 → 预览影响 → 保存 → 已开始计划保留原版本，新行动使用新值。
